# Plan: Production Readiness for async-crud-mcp as Claude Code CLI Replacement

## Context

**Problem**: async-crud-mcp provides 17 MCP tools for file operations with async locking and conflict detection, but it cannot yet replace Claude Code CLI's native tools (Read, Write, Edit, Glob, Grep, Bash). Critical gaps exist in regex editing, project activation workflows, security defaults, and performance at scale.

**Solution**: Implement three critical fixes (regex edit mode, auto-project detection, secure path validation defaults) plus six high-priority enhancements (external edit detection, large file streaming, shell validation robustness, distributed locking, search indexing, concurrent test coverage) to achieve production parity.

## Changes

### Critical Fixes (Required for Production)

#### ### File: `src/async_crud_mcp/tools/async_update.py` (L264-287)
- **Current**: Patch mode requires exact string matches only; no regex support
- **Change**: Add `regex_patches` mode with pattern/replacement pairs. Validate patterns compile before acquiring file lock, track match counts during substitution
- **Details**: Native Edit tool supports regex search-and-replace; this is high-friction for agents who fall back to full-content updates, increasing contention and token costs

#### ### File: `src/async_crud_mcp/server.py` (L213-239)
- **Current**: ProjectActivationMiddleware enforces explicit `crud_activate_project()` call before any CRUD operation
- **Change**: Auto-detect project root from first CRUD tool call's path; store session_id → project_root mapping internally. Remove hard requirement for activation call
- **Details**: Native Claude Code tools have no activation concept; this is a breaking change for agents. Auto-detection enables drop-in replacement without workflow changes

#### ### File: `src/async_crud_mcp/core/path_validator.py` (L153-156)
- **Current**: If `base_directories` is empty, PathValidator allows full filesystem access (no restriction)
- **Change**: Default to current working directory when `base_directories` is empty; add warning log for permissive configurations
- **Details**: Empty config creates security vulnerability; insecure defaults violate principle of least privilege

### High-Priority Production Quality Improvements

#### ### File: `src/async_crud_mcp/tools/async_update.py` (L219-247)
- **Current**: ContentionResponse on file modification doesn't distinguish user edits from agent-originated changes
- **Change**: Add `modified_by: "agent" | "external" | "unknown"` field to contention response; track modification source via agent request_id
- **Details**: Agents need context to decide whether to retry or abort on contention; currently they cannot distinguish user interference

#### ### File: `src/async_crud_mcp/tools/async_read.py` and `async_write.py` (L67-72, L113-123)
- **Current**: File size limit enforcement returns hard error; no streaming support for large files (max_file_size_bytes)
- **Change**: Implement `async_read_stream_tool` returning content in chunks; bypass size limit for streaming reads. Add streaming to write/update paths for large artifacts
- **Details**: Large log files, binaries, and generated artifacts are common in real projects; hard failure breaks workflows

#### ### File: `src/async_crud_mcp/core/shell_validator.py`
- **Current**: Shell deny patterns use regex word boundaries (`\bcat\b`); vulnerable to obfuscation (e.g., `c''at`, `$(echo cat)`)
- **Change**: Add AST-based shell parsing (not just regex). Detect command substitution, empty strings, and other evasion techniques
- **Details**: Agents or malicious prompts can bypass pattern matching; production security requires semantic validation

### Scalability & Performance Enhancements

#### ### File: `src/async_crud_mcp/core/lock_manager.py` (L49-150)
- **Current**: In-memory FIFO lock manager; no distributed support or deadlock detection
- **Change**: Add Redis-backed lock manager as alternative backend. Config option: `persistence.lock_backend: "memory" | "redis"`
- **Details**: Horizontal scaling impossible with in-memory state; multiple MCP server instances cannot share locks for large codebases with many agents

#### ### File: `src/async_crud_mcp/tools/async_search.py` (L23-186)
- **Current**: Linear scan using `Path.rglob()` + regex match; O(n) performance where n = file count × file size
- **Change**: Add optional trigram index built on project activation. Use index for fast pattern lookups instead of sequential file scans
- **Details**: Monorepos (>10k files) experience slow searches; no parallelization or mmap; unacceptable for large projects

#### ### File: `tests/test_lock_manager.py`
- **Current**: 128 unit tests total in codebase; lock manager tests lack concurrent race condition and deadlock scenarios
- **Change**: Add concurrent stress tests for multi-agent lock contention, deadlock detection, timeout handling, cross-file dependency scenarios
- **Details**: Lock manager is core concurrent safety mechanism; production reliability requires exhaustive edge case coverage

## Missing Features (Not Modified This Sprint)

The following exist in native Claude Code but are out of scope:

- **Notebook Editing**: No structured `.ipynb` cell-level operations (native has NotebookEdit tool)
- **LSP Integration**: No language server for symbol lookup, type hints, code navigation (native has LSP tools)
- **Task/Process Orchestration**: Shell execution only; no inter-task dependencies or multi-task status tracking (native has Task tool)

These are **low priority** and additive (not blocking production use).
